# 統合契約: Codexは配置・接地・QAのみ

## 1. 現行互換部材

推奨入力は両側をまとめ画像を共有した `current_pair.glb`。内部に左右別rootがあり、接地高さを独立調整できます。代替として左右別の `current_left.glb` と `current_right.glb` もあります。pairと左右別を同時にロードしないでください。両方ともハチ公周辺設備の既存ローカル原点を共有します。BlenderではZ上、glTF書出しは標準Y上です。左右の部品をそれぞれ原点へ再センタリングしないでください。

- 元の設備用xy原点(11.568175521259887, -48.68573220011713)とyaw=35°を使用します。機械可読の `MOUNTING.json` にglTF/Three.js変換も記載。これは像の最終姿勢が正しいという意味ではありません。
- 像スキャンのyawを校正しても、座面や低木のyawを自動で追従回転させないでください。像rootの向きと周辺設備の平面座標系は別です。
- 左右の地面高さは各区画の既存9点サンプル最小値（左0.4710693359375m、右0.4155540466308594m、TP=15m基準）を再使用、または同じ座標を元のground_sidewalkへ照会します。Blender/source Z=0（= glTF/Three Y=0）がその基準。土台を一括で0mに置かないでください。
- 非均等縮尺でごまかさずscale=1を使用。
- 幅2.35m、前面y=-1.0m、奥行0.75m、壁高0.52m、笠石上端0.59m、レール中心前0.65m/後0.81m、レール半径0.035mを継承。微小な端部継ぎ目の最大包絡は元の管面より0.7mmだけ大きくなります。
- 16分割の縦石張り、笠石目地、1個/側の低位置横長照明は写真に基づく見た目の改良です。分割数・照明寸法は実測値ではありません。背面区画外形は既存推定の維持です。

## 2. 旧資産と低木新作の選択的置換

旧 `build_surround.py` は役割別に材質結合済みです。そのまま新GLBを上乗せすると旧レールと石が重複します。

置換してよい旧役割:
- `street_surround_stone`: 左右のwall/cap/return/rear/rear_cap。旧記念碑が残っていないことを先に確認。
- `street_surround_silver`: rail/inclined_support/leg。
- `street_surround_panel`: wall_light。ただし旧石板の`unread_inscription`が残っている古い版を使わない。

残す旧役割:
- `street_surround_soil`
- `street_surround_rock`
- 新作低木のbranch/needle/needle_lightとその後継メッシュ
- `street/hachiko-memorial`、大木囲い、像、他の樹木

低木担当の `models/hachiko_low_shrubs_only_v002.glb` はbranch/needleのみで、ワールド配置とyawが焼き込み済みです。この座面パックの35°回転・xy原点・高さを低木へ再適用しないでください。両資産を同じ変換済み親へ入れると低木が二重移動します。旧branch/needleをその新作へ置換し、本パックの3役割置換とは分離します。もし別版の新低木パックが非低木部材を保持する場合は、その出力の上記3役割だけを無効化または削除します。ノード名が変わった場合は材質と生成役割を確認し、`surround`全体を丸ごと削除しないでください。共有のstreet_coreや全樹木の再生成も不要です。

新GLBは各側4メッシュ:
- `current_{left|right}__stone`
- `current_{left|right}__rails`
- `current_{left|right}__rail_hardware`
- `current_{left|right}__lighting_detail`

## 3. 曲線候補

`candidate_curve_*`は既定OFF。左右2つの開いた弧のみで全周を推定しません。半径4.0m、中心(0,2.4)、角度left200–258°/right282–340°は制作上の仮定です。撮影日不明の写真と同じ雰囲気を比較するための候補であり、工事後の現況座標として使わないでください。

候補を比べる場合も大木・大木囲い・既存樹木・像・低木を動かさず、干渉と視線を確認します。このパックは旧広場全体へ戻す指示ではありません。

## 4. 舗装候補

`candidate_paving_PREVIEW_ONLY.glb`は平坦な2三角形です。実シーンへ地面としてロードしないでください。

候補を検証する場合は、既存の切り抜き済み `plaza-finish` 三角形を維持し、実際のローカルx,yから次のUVを与え、自作アトラスだけを割り当てます。
- u = (x + 5.2) / 10.4
- v = (y + 4.0) / 7.0
- 範囲: x=-5.2..5.2、y=-4.0..3.0。

地面の頂点z、道路・歩行用サーフェス・既存1mm描画オフセット・範囲を変更しません。Three.jsのGLTFLoader規約でtexture.flipY=falseを守り、上面確認でY方向を取り違えないでください。

大円中心=(0,0)、敷石ピッチ約0.103m、外縁半径約3.56m、手前直線帯の角度は推定です。日付ありJuly写真にも曲線列は見えますが、外径・中心・帯の交点は未測量。現在の局所パッチは手前y=3mで切れるため、参照写真にある大円全体と長い帯をすべて含められません。無断で舗装範囲を広げず、この制約を残します。

## 5. 実シーンQAは統合作業

同一カメラのbefore/after: 地上正面、斜め、石材/レール近接、低木近接、全景、候補変更時は上面。

接地、二重配置、Z-fighting、低木/像/既存大木囲いへの干渉、昼夜の読みやすさ、材質テクスチャ、street=offと読込失敗、統合後のプリミティブ予算を確認してください。単体4メッシュ/側ですが8プリミティブ/側です。BOXやプロジェクトの上限を黙って緩和しないでください。
