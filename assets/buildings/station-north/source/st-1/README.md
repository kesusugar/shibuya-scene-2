# ST-1 選択入力と配置生成元

`placement.json` が今回のシーン配置の生成元。元候補のworld_transform=nullは0へ読み替えない。
リポジトリルートの `node scripts/build-st-1.mjs` で選択GLBから配信2 GLB、viewer、昼夜テーブル、
build-report、station-northのmanifestを更新できる。PR81後は `../st-1-opening/` の保存構造原本から
看板直下だけを切り欠いた配信構造GLBも生成する。原本・地面・この配置JSONは上書きしない。

各候補ディレクトリはDriveの検証済み完全ZIPから選んだ入力スナップショット。
原本MANIFESTは完全ZIPの記録なので、そこに載る全ファイルがこのリポジトリにもあるとの主張ではない。
GLB・生成ソース・README・出典／推定／選択資料・フォント通知・検証JSONを保持する。
blendとモデルのみのスタジオ画像、生成ログの一部は完全ZIP側に保持。調査写真は含めない。

候補自体を作り直す場合は、それぞれの原本READMEのBlender4.2.3コマンドを別出力先で使う。
看板生成ソースはOFLの改名済みサブセットを内包し、柱生成ソースも写真・外部ネットワーク不要。
再生成したGLBの採用は入力SHA-256を確認して明示的に行う。配置生成中に原本を再制作しない。

今回の配信加工：同じ正の等方変換を1回合成、看板材質を同値の独立材質へ分離、柱の底辺頂点だけ
既存の可視地面の5mm下へ合わせる。看板の形・文字・材質値と柱の上部・帯・法線・インデックスは保持。
細かな左右位置・公差・色・寸法・取付は推定。閉じた既存壁、隠れた支持部、内部の完成を主張しない。

元候補URL・ZIPハッシュ・出典時点と制約は [ST_1_REPORT.md](../../../../../docs/core/ST_1_REPORT.md) と
`delivery-verification.json`、各候補の原資料を参照。
