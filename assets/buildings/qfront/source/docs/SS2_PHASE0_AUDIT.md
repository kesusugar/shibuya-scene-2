## 4. 実測データの出所と高さの定義
- 旧データ `public/data/shibuya-scene-data.json`
  - 座標系：`X=東, Y=上, Z=南`、メートル単位、原点は北緯 35.6595・東経 139.7005。
  - OSM（ODbL、2026-09-08 取得、入力ファイルの SHA を記録済み）と、PLATEAU 2025 渋谷区 CityGML（4 タイル）。
  - 建物 666 棟、道路 306 本、横断歩道 118 か所、信号 49 基。
- **高さの定義の食い違い（パック 08 が警告している例そのもの）。** QFRONT の PLATEAU の値は 3 種類あります。
  - `measuredHeight` 45.9 m
  - LOD2 の屋根の最高点 52.13 m（王冠の上端）
  - 内側の屋根 48.4 m、段差の屋根 44.0 m と 39.8 m

  qfront-photoreal では、写真から測った王冠の高さ（52.1 m）と LOD2 の値が一致しています。`measuredHeight` は建物本体の高さとみなし、王冠や広告の高さとは別のものとして扱う必要があります。
- 座標系の対応
  - qfront-photoreal（Blender）：X=東、Y=北、Z=上。原点は同じ。
  - glTF の書き出しでは、標準の Y-up 変換（X, Y, Z）→（X, Z, −Y）がかかり、X=東、Y=上、Z=南になります。**旧データと同じ規約になるので、軸の変換は不要です**。G1 では、検証用のダミー（東西南北の矢印）で確認します。

## 7. G1（新しいビューア）と G2（QFRONT を WebGL で検証）の最小計画
1. **保全（承認後すぐ）**
   - qfront-photoreal の履歴を `shibuya-scene-2-` の `assets/buildings/qfront/` に移します（パック 04 の構成）。
   - あわせて `manifest.json`（座標、出典、ライセンス、ソースの SHA）を作ります。
2. **G1**
   - Vite + TypeScript + Three.js の小さなビューアを作り、`loadBuilding(id)` で建物を 1 棟ずつ読み込みます。
   - 読み込みに失敗したら、仮の箱とエラーを表示し、他の建物は表示を続けます。
   - 自動テストで、GLB の空メッシュ、NaN 座標、0 ポリゴン、材質の欠落を検出します。
3. **G2**
   - Blender から GLB を書き出します。王冠の鉄骨とフィンは実際の形状、ガラスは PBR で表現し、室内照明と夜の発光は焼き込み（ベイク）で再現します。
   - Cycles と WebGL を同じカメラ（Q032 と Q031）で並べて比べます。
   - オーナーの PC で、FPS（中央値と 95 パーセンタイル）、描画呼び出し数、ポリゴン数、テクスチャのメモリを計測します。

## 8. Cycles から WebGL へ移すときの品質リスク（v5 の作りに由来）
- v5 のガラスは、Cycles の Light Path ノードを使った工夫（影の計算用の光線だけガラスを素通しにする、カメラから見た空だけ色を変える）に依存しています。
- 後処理（色収差、周辺減光、光のにじみ）、面光源による投光器の照明、HDRI の映り込み（反射の光線だけで使用）も同様です。
- **これらは GLB には一切引き継がれません。** WebGL では、環境マップ、ベイクした発光や陰影、Three.js 側の後処理で作り直す必要があります。
- ポリゴン数は約 20 万です。部材が単純な箱の集まりなので、インスタンス化（同じ部材をまとめて描く方法）と LOD（距離に応じて簡略版に切り替える方法）が効きます。
- **予想**：形状と昼の印象は持ち込めますが、ガラスの反射と夜の光は品質が大きく落ちます。これを最初に数値と画像で示すのが G2 の目的です。

## 9. パックの記述で、間違いの可能性がある点
1. **QFRONT の所在**：パックは「旧リポジトリの別ブランチ」としていますが、実際は独立したローカルリポジトリで、未 push です（3 節）。
2. **新リポジトリの名前**：末尾にハイフンが付いています（6 節）。
3. **「GPU 非搭載」**：WebGL は CPU 内蔵の GPU（Intel Iris Xe や AMD Radeon Graphics など）で描画されます。そのため、「専用 GPU（グラフィックボード）なし、内蔵 GPU」として計測条件に記録するのが正確です。
4. **群衆 1,978 人**：パック 06 は「最初から全員を表示しなくてよい」としています。旧プロジェクトでの「1,978 人を減らさない」という約束とは別の判断になるので、2.0 では新しく決め直す、という扱いでよいか確認させてください。
5. **ライセンス**：OSM 由来のデータを公開リポジトリに入れる場合、ODbL の表示義務と、派生データベースの継承条件がかかります。PLATEAU は CC BY 4.0 互換の利用条件です。どちらも台帳に記録します。
