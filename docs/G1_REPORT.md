# G1 報告：新しい Three.js ビューアで QFRONT を 1 棟表示する

## 結論
**G1 の機能要件はすべて満たしました**（読み込み、昼夜の切り替え、360° 閲覧、地上視点での歩行、FPS の計測）。
ただし **FPS はまだ実測していません。** 理由は「計測」節を参照してください。オーナーの PC での計測をお願いします。

## 作ったもの（旧 Shibuya Scene の描画基盤はコピーしていません。すべて新しく書きました）
| ファイル | 役割 |
|---|---|
| `src/main.ts` | 描画ループ（AgX トーンマッピング、影）、画面上の操作パネル、URL での指定（`?time=day|night`、`view=q032|walk`、`dpr=`） |
| `src/world/buildings.ts` | `loadBuilding(id)`。**例外を投げない**：読み込みに失敗したら赤い仮の箱とエラーを表示し、他の建物は表示を続ける。資産の検査（メッシュが空、NaN 座標、三角形 0、材質の欠落、ありえない大きさ）も行う。昼夜で発光の強さを切り替える |
| `src/world/lighting.ts` | 昼：太陽の方位 152°・高度 38°（v5 と同じ）、街の HDRI を反射に使う。夜：夕景の HDRI を弱く使い、紺色の空、側面を照らす投光器 4 灯 |
| `src/controls/viewer-controls.ts` | 360° 閲覧（Orbit）、地上歩行（目の高さ 1.6 m、WASD と Shift、壁で止まる）、Q032 の写真と同じカメラ（中心をずらした投影を再現） |
| `src/perf/frame-stats.ts` | フレーム時間の中央値と 95 パーセンタイル、FPS、描画呼び出し数、三角形の数、メモリ、解像度 |
| `assets/buildings/qfront/source/blender/export_web.py` | Blender から GLB を書き出す。Cycles 独自の材質ノードを、glTF で表現できる単純な PBR 材質に作り直す。建物だけを書き出す（周辺の街並みや人は含めない） |
| `assets/buildings/qfront/web/` | `qfront.glb`（5.8 MB、115k 三角形、56 メッシュ）、昼と夜の発光の強さの表、`viewer.json`（カメラと太陽の位置などの情報） |
| `tests/` | 読み込み失敗時の分離（5 件）、出荷する GLB の検査（4 件）：計 9 件、すべて合格 |

## Cycles と WebGL の比較（同じ Q032 カメラ。`evidence/g1/compare_*.jpg`）
| 部位（平均 RGB） | 写真 | Cycles v5 | WebGL |
|---|---|---|---|
| 前面ガラス上部 | 86, 91, 98 | 95, 101, 106 | 102, 109, 113 |
| 前面ガラス中部 | 87, 89, 97 | 86, 91, 95 | 102, 108, 111 |
| 左側面 | 170, 171, 174 | 160, 162, 166 | 178, 177, 176 |

**WebGL で保たれたもの**：外形、フィンのリズム、王冠と文字、低層の帯と看板、昼夜の大まかな印象。

**WebGL で落ちたもの**（予想どおり）
- ガラスの反射が単純。Cycles のような、パネルごとのゆらぎや、近くの街の映り込みがない。
- 王冠の奥の陰影が浅い。
- 夜の店内照明の光のにじみや、間接光の回り込みがない。
- 周辺の街並み、人、車は意図的に書き出していない。

## 計測
- この環境のヘッドレスブラウザは、CPU 上のソフトウェア描画（SwiftShader）しか使えません。そこで出た値（2〜5 FPS）は**参考にならないので、合否の根拠にしていません**。
- 構成上の負荷の目安：描画呼び出し 46〜113 回、三角形 10 万〜23 万、テクスチャ 8 枚。
- **オーナーの PC での計測手順**
  ```
  npm ci
  npm run dev
  ```
  - ブラウザで `http://127.0.0.1:5180/` を開き、左上の数値（FPS、p50、p95）を 30 秒ほど見て記録してください。昼・夜、360°・歩行のそれぞれで計測をお願いします。
  - 重い場合は `?dpr=1` を付けて、解像度を下げた場合も比べてください。
