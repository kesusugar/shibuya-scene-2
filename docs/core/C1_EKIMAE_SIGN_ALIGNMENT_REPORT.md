# 駅前ビル：ガストなどの看板と階境界のずれを修正

ユーザーの指摘により、前版の比較画像を拡大して確認したところ、実際にずれがあった。主な原因は、曲がった正面と右側の面を一枚の四角形として切り出したことで、右側の切り出し位置が約 30 px ずれ、隣の階の広告を含めていたこと。さらに、写真の看板にない等間隔の立体的な縦桟を広告の上へ重ねていた。

## 修正

- EK01 の元画像（4032×2268、Joli Rumi、2025-11-01、CC BY-SA 4.0）で、9F / 8F / 7F の境界と外側の端を読み直した。
- 最初の修正案は各階を独立した 6 区画で補正したが、ユーザーの拡大画像で右側の向きがまだ傾いていると確認した。階ごとの横位置がずれていたため、この方式は採用しない。現行版は、9F〜7F の全高さを通した「正面」「右側」の 2 面を先に透視補正する。両面の共通の縦境界は元画像の (800,750) → (715,1010) を使用し、全階を同じ U 座標に揃える。次に横位置を一切ずらさず、縦方向だけで階の境界を整える。これにより同じ柱・窓枠が階ごとに別方向へ傾く問題を修正し、別階の文字と右端の 17LIVE のはみ出しも除く。
- 右側の「しゃぶ葉」を 9F 内へ収め、「コンタクト」の断片がガスト帯へ混ざらないようにした。
- 連続した看板の文字を横切る、根拠のない等間隔の縦桟を除去。階境界の細い横枠だけ残し、ガストの下には写真で確認できる白い幅のある水平帯を付けた。
- メッシュ上の階範囲は、ガスト 21.15–24.35 m、8F 24.35–27.70 m、9F 27.70–31.00 m。階の高さは写真と既存の外殻からの推定で、測量値ではない。

新しい切り出し手順は `source/blender/rectify_restaurant_signs.py`。`recrop_ek01.py` の最後から呼び出すため、元画像から再生成しても修正が維持される。元画素以外の文字・広告を生成していない。境界の画素座標と手法は `source/data/facades.json` の `restaurant_alignment` に保存。

## 比較と確認

- 拡大比較：`evidence/c1-ekimae-sign-alignment/comparison.jpg`。元写真、公開されていた直前の外装、今回の面方向を揃えた修正を並べた。`right-return-after-ja.jpg` はユーザーが指摘した右側だけの現在案。前後のモデルは同じカメラ・照明。
- `evidence/c1-ekimae-fidelity/` の正面・側面・全体比較も現在のモデルで更新。
- Blender 4.2.3 で GLB と編集用 blend を再生成。独立した再実行で GLB が一致し、元画像からの再切り出しでも全 PNG が一致。
- 合計 23,730 三角形、27 プリミティブ、2,088,436 bytes。既存の B 予算内。
- 元の壁・屋根の頂点、地理座標、T.P.15.29 m、Samsung のメーカー寸法を保持。他の建物を変更していない。
- 看板の有限性・境界・色と発光テクスチャ・画面寸法などの既存試験を維持。元の高所カメラからの 40 度の確認レイを維持し、20/60/80 度では面の外向き法線から短い確認レイを追加した（高所の同じ視点から遠い曲面を狙うと、手前の上階に自然に隠れるため）。階の上下端、全高の共通の縦境界と、上下の階で共有する補正後の Y 座標を確かめる試験も追加。
- 全体 npm / ブラウザ統合試験の制約は前報と同じ。個別の試験成功をプロジェクト全体の試験成功とは扱わない。

## 残る差

全高の面補正により、ユーザーが示した右側の柱・窓枠は共通の縦方向に揃った。ただし、2 面の展開幅比（682:342）、曲率、階高、現物の細かな面分割は写真からの推定で、完全な写真カメラ校正や測量ではない。文字を含む画素の解像度や局所的な曲面の歪みは残る。今回の問題を単に「残る歪み」として無視したものではなく、同じ箇所を拡大して向きが揃ったことを比較したが、「写真と完全に一致」とは扱わない。
