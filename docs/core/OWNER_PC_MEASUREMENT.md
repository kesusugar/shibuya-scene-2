# オーナーの PC での性能測定の手順（C2a 時点）

- この環境で測れるのは、画面なしの SwiftShader による値だけで、FPS としては使えない。
- そのため、**FPS の数値はオーナーの PC で測ったものだけを記録する**。
- 三角形の数と描画の呼び出し回数は、どの環境でも同じ値になるので、参考として C2a の報告書に記載している。

## 準備（Windows）

```powershell
cd shibuya-scene-2
git fetch origin
git switch claude/core-c2a-ground
npm ci
npm run dev
```

- 表示された URL（通常は `http://127.0.0.1:5173`）を、Chrome または Edge で開く。
- 他のタブやアプリは閉じる。ノート PC は電源につなぐ。

## 測る URL（各 30 秒）
各ページの右上にある「30秒計測」を押す。終わると JSON が表示されるので、それをすべてそのまま貼り付けて送ってほしい。

| # | 内容 | 追加する URL の末尾 |
|---|---|---|
| 1 | 交差点中心から QFRONT、昼、**地面あり** | `?time=day&pose=6.5,-2.0,1.516,-8,29,12,55` |
| 2 | 同じ視点、**地面なし**（地面の負荷を切り分ける） | `?time=day&pose=6.5,-2.0,1.516,-8,29,12,55&ground=off&datum=off` |
| 3 | 同じ視点、夜 | `?time=night&pose=6.5,-2.0,1.516,-8,29,12,55` |
| 4 | 高所 X01（駅の連絡通路の窓、REF-A） | `?time=day&pose=-12.6,-68.2,10.2,0.8,30.7,16.2,52.2` |
| 5 | 真上から（地面全体が写る、最も重い条件） | `?time=day&pose=6.5,-30,190,6.5,-1.9,0,48` |
| 6 | 歩くモード（W・A・S・D で 30 秒歩く） | `?time=day&view=walk` |
| 7 | 画質「低」で 1 と同じ視点 | `?time=day&q=low&pose=6.5,-2.0,1.516,-8,29,12,55` |

## 合わせて知らせてほしいこと
- CPU と GPU の名前（JSON の `gpu` 欄に出ない場合）。
- メモリの量。
- 画面の解像度と、Windows の表示倍率。
- 体感：カクつく場面があったか。地面のちらつきや、縁石の欠けが見えたか。

## 判断の目安（目標であって、約束ではない）
- 1 と 2 の差が、地面の負荷にあたる。
- 1 の FPS が 2 の 85% を下回る場合は、地面を軽くする（歩道の分割を粗くする、遠くの地面を簡略化する）。
- これは C3 の前に行う。
