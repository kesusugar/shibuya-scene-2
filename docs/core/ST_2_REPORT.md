# ST-2：ハチ公前交番の可視外観

PR82マージ後main `ecd30e7` からの独立取り込み。通常表示へ `hachiko-policebox` を追加し、
対応する駅西面の壁・仮囲いだけを局所置換する。ST-2の浅い外観の範囲であり、第3段階全体ではない。
交番の全棟・裏面・内部・警察設備・地下・入室機能、宝くじ・A8・ルーバーは制作しない。

## 実保存と検証

Google Drive MCPのmetadata確認後、`fetch(download_raw_file=true, include_base64=false)` の
トップレベルfile_uriに含まれるダウンロード先から、一時フォルダへ実ZIPを保存した。
API応答成功と実保存成功を両方確認し、共有変更・制限回避は行っていない。

- ZIP：6,061,533 bytes、SHA-256 `575d5eddc484263e43f314b12309c9c92e84d190e6912deceefe3fc10b3e7dfa`。
- 全CRC正常、絶対／親逸脱／ドライブ指定／symlink不在を確認して安全に展開。
- `MANIFEST.sha256` の18ファイルを全件照合。GLBとblendの収録を確認。
- 原本GLB：522,776 bytes、SHA-256 `f7d20e04dcc39e67f42acb48656424dcb37ef9fcc17cde7ff6b1b90a0810bc24`。
- 索引も実保存し、367,076 bytes、従来SHA `2616fa98aea09fbb9e4cc776715f9660c0047232b5fd94ecb5839c8e91a958d8` と一致。

`PACKAGE.json` は索引に記載される別の受領記録で、当該ZIPにはない。
ZIP内README・出典・推定寸法・生成元・原検証結果・manifestを読み、選択スナップショットと
今回の全CRC／一覧／ハッシュ照合記録を `assets/buildings/hachiko-policebox/source/st-2/` に保存する。
blend・原単体レンダーはDrive原本に残す。署名URL・認証情報・調査写真は収録しない。

## 同定・位置・正面

[渋谷文化プロジェクトの記事](https://biz.shibuyabunka.com/watch/50/)で2025-04-09撮影と記された
原写真P1/P2を画素で確認し、収録SOURCE_REGISTERの両SHAと一致した。
両写真に共通する曲面の緑／銀の帯、銀の外枠と庇、支柱と赤帯を対象とする。
写真の左（北）に公共高架下通行部、右（南）に旧改札側の表示・仮囲いがあり、宮益坂側のJR入口とは別面である。

[警視庁の渋谷駅前交番案内](https://www.keishicho.metro.tokyo.lg.jp/about_mpd/shokai/ichiran/kankatsu/shibuya/koban/06.html)
の施設名・住所と、そこからリンクされた地図のPOI（35.6592949, 139.70103）を確認した。
プロジェクトの地理原点（35.6595,139.7005）で概ねX=47.9m、北Y=-22.7m。
これは施設同定の点であり、正面アンカーの測量値ではない。

既存station-northのPLATEAU西面北端 `[47.764,-20.088]` から `[51.934,-60.248]` の線上を照合し、
北端から3.1m南の区画を選ぶ。単一配置行列のworld原点は `[48.044380,-0.34,23.175554]`、
Y回転-84.071956°、均等倍率1。正面は広場側（ほぼ西）、右は南。
上下軸は原GLBで既にY-upのため再変換しない。地理座標nullを0として使っていない。

通常表示の可視地面を照会した代表点はworld Y=-0.244〜-0.264m。
原本下部の支柱足・敷居を軽く埋めるよう基準Y=-0.34mとした。地面は変更しない。
幅5.2m・高さ6.6m、曲率、3.1mの取付距離、奥面深さ、部品足元は推定で、測量精度や写真校正誤差を主張しない。

BOX、未同定plaza-kiosk、駅西側設備棟、A8を交番として利用していない。
該当正面は独立C建物ではなく既にstation-northの壁に内包されるため、contextの全棟除外は追加しない。

## 採用・省略・局所置換

曲面帯・細線・銀色枠／庇・3か所の独立した支柱・赤帯・上部窓代理・下部の浅い枠と敷居を採用。
緑の帯の物理材質は未同定であり、ガラスブロックやルーバーとは断定しない。
任意のKOBAN表示は簡略同定補助で、公式の正確なロゴ・銘板・掲示ではない。
下部の元推定背板1部品だけを省き、局所開口の暗い閉鎖奥面へ置き換える。
群衆に隠れた下部の枠・支柱継続は元候補からの推定であり、実写確認済みとは扱わない。

原本を保持した `station-north-pr82.glb` から、`stn_concrete` の元三角形0・507だけを矩形クリップ。
手前の `stn_hoarding` の元三角形0・3にも同じ幅の矩形を適用し、正面に重なる仮囲いを除く。
切除面積は元壁約33.176㎡、仮囲い約15.600㎡。対象外の全三角形・属性・材質・変換、屋根・庇・構造柱と公共通行部、東側JR入口を保持する。
左右・上の見込みと、元壁から0.70m奥の暗い閉鎖奥面を追加。黒板を旧壁の手前に貼る方法ではない。
新しい室内・床は追加しない。元候補の推定敷居は外装部品としてのみ残す。

配信用は元部品を材質単位にまとめ、12,088三角形・11プリミティブ・549,056 bytes。
壁は通常本体、簡略表示は `signs_2025-04-09` レイヤー。上部窓代理だけglass、他はwall分類。
窓代理は元候補の不透明な浅い代理面を維持し、透視可能な室内は作らない。
発光は原本同様ゼロで、夜間点灯を創作しない。分類・環境反射・昼夜切替は既存規則を使う。

`node scripts/build-st-1.mjs` で、ST-1→ST-2の局所加工、両素材とmanifestまで再生成できる。
元候補の再生成には収録PythonとBlender 4.2.3を使用する。今回は取得済みの原GLBを入力とした。
既存原本・設定を重ねず、配置行列は各部に1回だけ適用する。

## 検証・制約

全体254件中253件成功、既存PARCOの重いレイ検査1件がこのWindows環境で5秒を超過した。
テストコード・形状・予算を変更せず、当該ファイルを `--maxWorkers=1 --testTimeout=20000` で再実行し16件すべて成功。
交番の新規5件、既存JR入口、対象外保持と予算の検査は標準設定で成功。型検査を含むビルドも成功。
CIの標準設定結果はPRに追記する。

実GLBで原部品の頂点形状・三角形数と単一配置、対象外の全元三角形／属性の保持、開口の奥面・斜めの見込み・裏面閉鎖、
原JR看板／柱／配置／昼夜設定の同一SHA、通常ローダーとsign／glass／wall分類を検査する。
既存予算値を変更せず、新しい交番のB登録だけを追加する。
駅本体とJRレイヤーの配信合計は5,715三角形・31プリミティブ・324,204 bytes。
交番も駅も既存B上限120,000三角形・40プリミティブ・3MB内で、全体予算検査も成功。
地面・歩行高さ・衝突処理・FPSの実装は変更しない。既存の建物レイ判定は浅い奥面で遮断され、入室可能な入口とは扱わない。

同一カメラの全景・正面・斜め・足元、通常／分類／昼夜の結果は [evidence/st-2](../../evidence/st-2/README.md) に記録する。
撮影中は資産・srcを固定し、ブラウザは1つずつ実行。写真の人物・告知・広告は制作・再配布しない。
全4視点の前後でカメラと取得成功を照合。正面・斜めで曲面帯、庇・支柱・赤帯、後退した入口を確認し、足元の浮きや公共通行部への新たな閉塞を認めない。
初期の北側斜めは既存樹木で隠れたため、樹木を動かさず南側斜めへカメラだけを変更し、前後を統一した。
分類はsign黄・上部窓代理glass青・帯と柱wall赤。通常の昼→夜→昼は画像完全復帰、1秒間隔の非停止画像も一致、取得・レイヤー・コンソールエラーなし。
既存の屋根影・照明下で銀／緑帯は写真より暗めに見える。現地光量に合わせた照明変更は行わない。
再生成コマンドの再実行は全対象ファイルでバイト同一。最後に追加した元三角形インデックス保持の検査も5件成功し、型検査も成功した。
