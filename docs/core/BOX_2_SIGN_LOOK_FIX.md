# BOX-2：看板レイヤー分類の修正

PR #79マージ後のmain `b0ce9d2` からの独立修正。6表示の生成元
`assets/buildings/shibu-hachi-box/source/exterior-signs/placement.json` のキーに
`signs_` を付け、既存のloaderが作る親名を `shibu-hachi-box:signs_…` にした。
既存の `/:signs/` 判定に一致するため、分類表示だけでなく通常の `applyLook` も看板として扱う。
共通判定・共通look設定・他建物は変更していない。

`node scripts/build-box-exterior.mjs` でviewer.jsonとmanifestを再生成した。
生成時には看板キーの規則とキー重複を検査する。
既存ブラウザ確認スクリプトも生成元から期待キーを取得し、件数だけで成功としない。
日付を含む各キーの意味と参照先GLBは保持した。

## 実アセットの回帰検査

`tests/box-sign-look.test.ts` は配信中の本体と6 GLBをThreeのGLTFLoaderで読み、
実運用の `loadBuilding` で親名を構成する。Nodeでは画像デコードだけTextureへ置き換える。
形状・階層・PBR材質は実ファイルで、元画像のピクセル・UV保存は既存のBOX-2テストを再利用する。

- 全6レイヤー・16プリミティブが分類表示で黄色の看板になる。本体には壁分類が残る。
- 通常表示の看板に壁用環境マップ／反射倍率が上書きされない。本体の壁には従来どおり適用される。
- 夜の既定倍率1では見逃すため、回帰検査には `nightSign=0.37` を使う。全6レイヤーで昼は強度維持、夜は倍率適用を確認。
- 生成元・viewer対応表とmanifestのサイズ／SHA-256を照合。

修正前の実ファイルでは命名検査と壁用環境マップ非適用の検査が失敗した。修正後は成功。
全体241テスト（54ファイル）、型検査を含む本番ビルド成功。既存予算テストも成功。

## 比較と不変条件

`scripts/check-box-sign-look.mjs` で通常の街の建物一覧・既定品質を使用。
同一の屋根近景と時計近景で、通常昼／通常夜／分類表示を前後撮影し、
通常表示はUIの昼→夜→昼操作を行う。昼へ戻したPNGは最初の昼と同一であることも検査する。
全6表示のロード成功、layerErrors・資産失敗・ブラウザエラー0を確認する。
画像は現地夜景との光量照合やFPS計測ではない。

比較画像とログは [evidence/box-2-sign-look](../../evidence/box-2-sign-look/)。
変更前は修正前main相当のビルド、変更後は本修正のビルドを使用し、撮影中は同期・ビルドしない。

`invariance.json` にmainと全7配信GLBのSHA-256一致を記録した。
本体と6表示の形状・配置・材質・画像はバイト単位で同じ。
配置JSONは6つのlayer値以外同じ。BOX合計は従来どおり
**2,734,704 bytes / 54,793三角形 / 30プリミティブ**で予算を緩和していない。

時計は既存の窓枠で一部遮蔽される。この制約を残し、窓枠削除・時計移動はしていない。
年代混在、推定寸法・取付、静止時計等の[BOX-2報告](BOX_2_REPORT.md)の制約も保持する。
看板分類の修正完了は第2段階全体の見え方完成を意味しない。マージ・デプロイは実施しない。
